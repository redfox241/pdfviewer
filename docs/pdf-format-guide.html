00
The short version / 一句话

PDF 记录的是排版结果，不是写作过程

Word 保存的是“这些文字组成一个段落”；PDF 保存的是“这个字形放在这个坐标上”。前者需要重新排版，后者不需要。

Layer 1

页面是画出来的

每一页由一组绘图指令组成：移动坐标、设置字体、画线、贴图片、显示文字。像一张已经排好版的透明胶片。

Layer 2

文件是对象图

页面、字体、图片、链接、表单、签名都是对象。对象之间用编号互相引用，形成一张可以增量修改的图。

Layer 3

阅读器是解释器

PDF 不是“打开就播放”的视频。阅读器要解析对象、还原字体、执行绘图指令，才能把页面画出来。

“PDF 的目标不是让你编辑它，而是让它在任何设备上都长得一样。”

这也是为什么 PDF 在合同、论文、发票、简历、印刷稿里活得很好：这些场景里，“看起来一致”比“方便改”更重要。代价是，PDF 天然不擅长像 Word 那样重排段落。

01
Origin / 来历

它原来的名字，叫“PostScript 的快照”

1993 年，Adobe 发布 PDF 1.0 和 Acrobat 1.0。PDF 的基因来自 PostScript：一种描述页面如何打印的编程语言。

PostScript 很强大，但它是一门语言，需要解释器，也可能包含复杂逻辑。PDF 把“最终要画成什么样”固定下来，变成一份静态的描述：不再执行排版逻辑，只按坐标把结果画出来。

所以 PDF 从出生起就带着两个性格：像程序一样结构化，像纸张一样固定。它既能保存字体和矢量图形，也能被增量更新、加密、签名，甚至嵌入 JavaScript 和附件。

1993Adobe 发布 PDF 1.0 与 Acrobat，目标跨平台保持一致。
2008PDF 1.7 以 ISO 32000-1 发布，PDF 成为公开国际标准。
2017ISO 32000-2（PDF 2.0）发布，清理旧包袱并增强安全与标签。
今天从发票到论文，从印刷到归档，PDF 仍是“最终版”的默认容器。
一个容易忽略的点：PDF 成为 ISO 标准，不等于所有 PDF 都遵守标准。现实中的文件可能来自几十种生成器，带着各自的扩展、损坏和怪癖。
02
Anatomy / 解剖

一个 PDF 的骨架，比想象中朴素

把 PDF 用文本编辑器打开，通常能看到文件头、对象、交叉引用表、尾部和结束标记。二进制的部分只是被压缩或编码了。

文件结构示意Fig. 01 — PDF anatomy
%PDF-1.7
% 文件头：告诉阅读器版本

1 0 obj
<< /Type /Catalog /Pages 2 0 R >>
endobj

2 0 obj
<< /Type /Pages /Kids [3 0 R] /Count 1 >>
endobj

... 页面、字体、图片、内容流 ...

xref
0 4
0000000000 65535 f
0000000015 00000 n
0000000064 00000 n
trailer
<< /Root 1 0 R /Size 4 >>
startxref
8831
%%EOF
H文件头：以 %PDF- 开头，声明版本。它不一定代表真实兼容性。
O对象：编号 + 内容。页面、字体、图片、注释、表单字段都是对象。
X交叉引用表：记录每个对象在文件中的字节位置，相当于目录索引。
TTrailer：指向文档根对象，也可能带加密字典、文件 ID 等信息。
E%%EOF：结束标记。增量更新后，文件里可能出现多个 %%EOF。
现代 PDF 还可能使用压缩对象流和交叉引用流，外观不再这么直白。

增量更新是 PDF 一个很聪明的设计：修改文件时，不必重写整个文件，只要在末尾追加新的对象和新的交叉引用表，再把 startxref 指向最新位置。旧数据仍然留在文件里。

这解释了两件事：为什么有些 PDF 越改越大；为什么“删除敏感内容”不能只靠肉眼看不见——旧版本可能还在文件里，需要真正的清理与重写。

03
Page model / 页面模型

PDF 里没有“段落”，只有落在坐标上的字形

一页 PDF 的核心是一段内容流（content stream）：一串操作符，告诉阅读器在什么位置、用什么字体、画什么。

一页的最小绘图指令Fig. 02 — content stream
q                         % 保存当前图形状态
1 0 0 1 72 720 cm         % 平移坐标系
BT                        % 开始文本对象
  /F1 24 Tf               % 选择字体与字号
  (Hello, PDF) Tj         % 在当前位置显示文字
ET                        % 结束文本对象
Q                         % 恢复图形状态
坐标原点默认在页面左下角，单位是 1/72 英寸。1 英寸 = 72 PDF 点。
Vector

矢量图形

线条、曲线、填充、裁剪路径。放大不会糊，因为保存的是几何指令，不是像素。

Raster

位图图像

照片和扫描件通常是位图：JPEG、JPEG 2000、CCITT 传真或 Flate 压缩的像素。

Text

文本对象

字形按坐标放置。阅读器知道每个字在哪，却不一定知道它们属于哪个句子或段落。

这也解释了“选区为什么是矩形”：阅读器根据字形的边界框拼出选区。跨行、跨栏、旋转页面时，矩形会变得不连续，但底层并没有“段落”可供选择。
04
Text / 文本提取

复制出来的字，为什么有时是乱码

字形不是 Unicode。PDF 里显示的是字体中的字形编号，复制文字时，阅读器需要把编号映射回字符。

01字形编号

页面里写的是字体内部的 glyph ID 或字符码，不是“你看到的汉字”。

02字体编码

简单字体用单字节编码；CID 字体可能用多字节编码，字符集各不相同。

03ToUnicode

可选的映射表，告诉阅读器“这个字形对应哪个 Unicode 字符”。

04Unicode

有了映射才能正确复制、搜索；没有映射时，阅读器只能猜。

常见情况有三种：

第一种，字体带 ToUnicode。复制、搜索通常正常。多数现代生成器会写入这张表。

第二种，字体没有 ToUnicode，或者映射不完整。阅读器可能根据字形名、编码表或 OCR 猜测，于是出现缺字、错字、顺序颠倒。

第三种，扫描件。页面本身就是一张图，根本没有文本层。想复制或搜索，必须先做 OCR（光学字符识别），再把识别结果作为隐藏文本层叠回去。

所以，“PDF 能搜索”不是天生能力：它取决于生成时是否写入文本，以及文本是否可被正确映射。扫描件和“图片型 PDF”是两个不同的问题。
05
Resources / 资源

字体、图片和压缩，决定了文件的手感

一个 PDF 可能只有几十 KB，也可能有几百 MB。差别通常不在文字，而在字体、图片和编辑历史。

Fonts

字体嵌入

为保证跨设备一致，PDF 可以嵌入字体，甚至只嵌入用到的字形子集。嵌入越完整，文件越大，但越不依赖系统字体。

Images

图片压缩

照片常用 JPEG；扫描件常用 CCITT 或 JPEG 2000；图标和线条可能用 Flate。压缩方式不同，清晰度和体积也不同。

History

编辑历史

增量更新会保留旧对象。一个被反复修改、签名的 PDF，可能比最终看到的内容大很多。

过滤器常见用途特点
FlateDecode文本、矢量、无损图像DEFLATE 压缩，PDF 里最常见的通用压缩。
DCTDecodeJPEG 照片有损压缩，体积小，文字边缘可能发虚。
JPXDecodeJPEG 2000 图像支持更高压缩比与无损模式，解码更复杂。
CCITTFaxDecode黑白扫描件传真式压缩，适合纯黑白页面。
RunLengthDecode简单位图古老的行程编码，现代文件较少见。

“文件小”不等于“质量差”，“文件大”也不等于“清晰”。一张被反复转存的高清扫描图，可能又大又糊；一份纯文字 PDF，可能只有几百 KB 却字字清楚。

06
Family / 家族

PDF 不是只有一个版本，而是一整个家族

ISO 32000 是核心规范；在此之上，还有面向归档、印刷、无障碍和工程的子标准。

标准面向关键约束
PDF/A长期归档字体嵌入、颜色自包含、减少外部依赖，强调几十年后仍可读。
PDF/X印刷交换固定输出意图、色彩与出血要求，减少印前意外。
PDF/UA无障碍标签结构、阅读顺序、替代文本，让辅助技术能理解内容。
PDF/E工程文档面向 CAD、图层、测量与大型图纸的交换。
PDF/VT可变数据印刷大批量、个性化印刷，如账单、直邮。
版本时间代表性变化
PDF 1.42001透明度、JBIG2、更完整的图像模型。
PDF 1.52003对象流、交叉引用流、可选内容图层。
PDF 1.72006成为 ISO 32000-1 的基础；AES 加密等扩展。
PDF 2.02017清理旧特性、增强标签与安全；XFA 不再属于核心规范。

版本号只是能力上限，不是质量保证。一个标着 1.7 的文件可能很规范，一个标着 2.0 的文件也可能来自粗糙的生成器。

07
Security / 安全

密码、权限和签名，不是同一件事

PDF 支持加密、权限控制、数字签名，也支持 JavaScript 与附件。能力越多，边界越需要说清楚。

Password

两种密码

用户密码用于打开文件；所有者密码用于限制打印、复制、修改。权限是阅读器执行的约定，不等于强加密。

Signature

数字签名

签名验证“文件在签署后有没有被改”，通常依赖增量更新与证书链。它证明完整性，不负责给文件加密。

Active

活动内容

JavaScript、嵌入文件、外部链接、3D/多媒体都可能存在。打开陌生 PDF 时，限制这些能力是合理的。

还有一个常见误区：把“不能复制”当成“内容安全”。屏幕可以截图，页面可以拍照，权限控制只能提高门槛，不能替代真正的访问控制。

对敏感文档，真正有效的是：加密、最小权限、受控分发、审计，以及在撤销访问时让旧文件失效——这些都不是 PDF 格式本身能单独解决的。

08
Myths / 误解

六个常见误解，一次说清

PDF 太常见，反而容易被当成“一个后缀”。下面这些说法，至少有一半是错的。

01“PDF 就是一张图片”

不一定。它可以是矢量图形、可选文本、表单、图层，也可以包含位图。扫描件只是其中一种。

02“扫描件也能直接搜索”

不能。图片没有文本层，必须先 OCR，再把识别结果叠回去。

03“改 PDF 会像 Word 一样重排”

不会。PDF 保存的是固定坐标，编辑通常是在对象层面替换文字或图形，不负责重新流式排版。

04“有密码就是加密了”

打开密码和权限密码不是一回事；权限限制也不等于内容被强加密。

05“文件越小越不清晰”

不一定。纯文字和矢量图可以很小；图片压缩方式才是清晰度的关键。

06“PDF 只能看”

它可以有表单、注释、签名、附件、图层、3D 和音视频。只是并非所有阅读器都支持全部能力。

09
Practice / 这个阅读器

我们选择“只读原文，旁挂阅读数据”

理解了 PDF 的对象与坐标，就能理解这个阅读器的取舍：渲染交给 PDF.js，标注与进度存在本地数据库，原文件不动。

Render

PDF.js 负责还原页面

用 canvas 画页面，用文本层承载选择与搜索，尽量接近浏览器里的 PDF 体验。

Annotate

标注是独立数据

高亮、下划线、便签、手绘都存成结构化记录，不写回 PDF，避免破坏原文件与签名。

Translate

翻译是可选插件

在线翻译与离线词典都以插件提供，默认不联网；整句翻译后还能逐词回看音标与释义。

这不是“不能编辑 PDF”，而是刻意把“阅读”和“修改原文”分开。原文件是证据，阅读数据是笔记；两者各自保存，互不污染。

“格式的价值，不在于它多复杂，而在于它让多少人不必解释自己看到的是什么。”
10
Appendix / 附

一份最小术语表

下次再遇到“PDF 打不开”“复制乱码”“文件太大”，可以先从这些词开始排查。

对象 Object PDF 的基本存储单元，用编号和代数标识。
交叉引用表 xref 记录对象字节偏移的索引，决定阅读器如何找到对象。
内容流 Content Stream 页面上的绘图指令序列，描述“画什么、画在哪”。
资源 Resources 页面引用的字体、图片、图形状态等外部对象。
CID 字体 用多字节字形编号组织大量字符，常见于中日韩字体。
ToUnicode 字形编号到 Unicode 的映射，文本复制与搜索的关键。
增量更新 在文件末尾追加修改，不重写旧内容；签名与编辑历史依赖它。
PDF/A 面向长期归档的 PDF 子标准，强调自包含与可重现。
OCR 光学字符识别，把扫描图像转成可搜索的文本层。
线性化 为网络快速预览优化过的 PDF 布局，也称 Fast Web View。
